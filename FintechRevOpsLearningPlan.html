How this plan works

This is a 16-week self-paced study plan built to make you conversationally fluent, then technically competent, across the topics that show up daily in your Intuit Partnerships role and beyond.

Every concept card is now a direct link. Click any card labelled with a ↗ icon and it will open a specific video, article, tutorial, or doc that teaches that concept. No hunting.

Weekly structure: (1) learning objectives, (2) clickable concept cards each linking to real content, (3) curated deeper resources for the week, and (4) practical application.

The arc

Month 1 puts down the fintech foundations: payments, lending, business models, unit economics.

Month 2 extends fintech into growth, competitive landscape, SMB, and cross-jurisdictional regulation, then starts AI from first principles.

Month 3 goes deep on enterprise AI, MCP, AI partnership economics, and starts the SQL zero-to-hero track.

Month 4 finishes SQL, builds RevOps and product marketing fluency, and closes with Claude mastery covering Chat, Cowork, Code, and context engineering.

Week 10 · MCP 101 + MCP Partnerships

By end of week: you can explain what Model Context Protocol is, why Anthropic open-sourced it, what an MCP server does, and how MCP is emerging as a new fintech / SaaS distribution channel.
▾
MCP Fundamentals (click any card)
What MCP isOpen protocol letting LLMs connect to tools, data, and prompts through a standard interface. Why it existsBefore MCP, every AI app had bespoke integrations. MCP is the "one adapter" pattern. Server vs ClientServer exposes tools/resources. Client (Claude, Cursor, IDE) consumes them. Tools, resources, promptsThree primitives an MCP server can expose. Local vs RemoteMCP servers can run on your machine (stdio) or as hosted services (SSE, HTTP). AuthOAuth, API keys, per-user tokens. Same patterns you know from partnerships.
MCP Partnerships & Partnership Models (click any card)
MCP as distributionWhoever's MCP server the LLM consults becomes the default answer. New distribution surface. Directory presenceBeing listed in Claude's or Cursor's MCP registry equals app-store placement. Commercial modelsFree/marketing, tiered API/usage, rev-share with the AI platform, enterprise-only. Data-in vs Action-outRead-only MCP servers vs write-enabled. Different risk profiles. Fintech implicationsPayments, accounting, capital APIs exposed via MCP become "agent-consumable." GovernanceHow AI platforms will curate MCP directories. Trust, security review, splits.

This Week's Practice

Build three of your own Claude Skills for your job. Suggestions: partnership-memo (drafts a partnership brief in your voice), pipeline-summariser (turns messy Salesforce exports into a weekly leadership summary), market-map-maker (generates a competitor teardown from a list of URLs). Save them. Watch how much faster your week becomes.

The capstone

In your final week, pull all of it together. Pick one real Intuit partnership initiative (Revolut expansion, a new fintech vertical, or an AI-agent integration) and produce a single artefact that touches every capability you have built.

  • Positioning written in April Dunford's frame.
  • Unit economics modelled with the right take-rate and CAC assumptions.
  • Competitive landscape mapped and referenced.
  • SQL query pulling partner-sourced pipeline directly.
  • RevOps attribution model spelled out.
  • PMM launch plan with KPIs.
  • AI angle: how MCP or agentic AI reshapes it in 24 months.
  • Regulatory considerations across the target markets.
  • Claude used throughout - Chat for drafts, Cowork for the deck, Code for data pulls.

The output is not the point. The point is that if you can put this document together end to end, you have crossed a line you cannot un-cross. You are fluent.
